# Чеклист безопасности перед релизом (Бармалей)

Практический чеклист под лендинг + админку. Пройти перед деплоем.

## 1. Секреты и конфиг

- [ ] В репозитории нет `.env`, `.env.local`, `config.yml` с паролями/ключами (проверить `.gitignore`)
- [ ] Нет секретов в коде (`API_KEY = "..."`, `JWT_SECRET = "..."`)
- [ ] Секреты только в переменных окружения (Vercel/сервер)
- [ ] В фронт не попадают ключи БД, JWT-секреты, ключи API

## 2. Аутентификация (админка)

- [ ] Пароли хранятся только в виде хеша (Argon2id/bcrypt)
- [ ] Rate limiting на логин (ограничение попыток входа)
- [ ] Нет дефолтных логинов (admin/admin и т.п.) в проде
- [ ] JWT/сессия с экспирацией; эндпоинты админки проверяют авторизацию на каждом запросе

## 3. Ввод и инъекции

- [ ] Валидация всех форм на бэкенде (Zod или аналог)
- [ ] Параметризованные запросы/ORM, нет конкатенации пользовательского ввода в SQL
- [ ] Вывод пользовательского контента экранирован (защита от XSS)

## 4. Деплой и конфигурация

- [ ] В проде только HTTPS, редирект HTTP → HTTPS
- [ ] Security-заголовки: `X-Content-Type-Options: nosniff`, `X-Frame-Options`, базовый CSP
- [ ] CORS не `*` с credentials; только нужные домены
- [ ] Debug выключен в проде; пользователю не показываются stack trace и детальные ошибки

## 5. Зависимости

- [ ] Используется lock-файл (`package-lock.json`)
- [ ] Перед деплоем выполнен `npm audit`, критические уязвимости исправлены

## 6. Админка

- [ ] Доступ по паролю; все эндпоинты `/api/admin/*` проверяют авторизацию
